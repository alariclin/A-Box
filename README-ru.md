Набор инструментов для развёртывания сетевого шлюза Linux одной командой.

A-Box — автономный Bash-скрипт для развёртывания и обслуживания сетевых шлюзов Linux. Совместимые версии по умолчанию: Xray `v26.7.28` (upstream prerelease, намеренно сохранённый как compatibility pin), sing-box `v1.14.3` и Hysteria `app/v2.13.0`; выбор последней стабильной версии не должен незаметно понижать уже установленное более новое ядро.

Поддерживаются Xray-core, sing-box, официальный сервер Hysteria 2, VLESS Vision REALITY, VLESS XHTTP REALITY, Shadowsocks-2022, экспорт клиентских конфигураций, локальная проверка кандидатов SNI, резервное копирование и восстановление, управление брандмауэром, диагностика, лимиты трафика, проверки состояния и обновление основных компонентов.

> Используйте проект только в законных, разрешённых и соответствующих требованиям средах. Пользователь несёт ответственность за все правовые, эксплуатационные и связанные с безопасностью последствия.

## Правовые условия и отказ от гарантий

Проект предназначен для тестирования сетевой архитектуры, исследований в области кибербезопасности, автоматизации системного администрирования и законной защиты конфиденциальности в полностью авторизованных средах. Не используйте его для незаконных атак, несанкционированного доступа, обхода аудита, злоупотребления сетью, нарушения работы инфраструктуры или иной противоправной деятельности. Используйте его только на серверах, в сетях и системах, которыми вы владеете, управляете или для которых получили явное разрешение.

Проект предоставляется «как есть», без гарантий. Перед запуском изучите скрипт и возможные изменения системы; перед обслуживанием или обновлением сохраняйте восстанавливаемые резервные копии.

## Быстрый старт

### Официальный источник GitHub

```bash
curl -fsSL https://raw.githubusercontent.com/alariclin/A-Box/ded204e4b7f718990a518fb5c1bcc1215d31c43c/install.sh -o A-Box.sh && sudo bash A-Box.sh
```

### Резервное зеркало третьей стороны

```bash
curl -fsSL https://mirror.ghproxy.com/https://raw.githubusercontent.com/alariclin/A-Box/ded204e4b7f718990a518fb5c1bcc1215d31c43c/install.sh -o A-Box.sh && sudo bash A-Box.sh
```

Обе команды привязывают установщик к неизменяемому commit `a7cb193e6539cee6478648e766f5ce415ccd5d41`; proxy URL остаётся сторонним транспортом, а не официальным endpoint A-Box. Для production проверьте commit и checksum через независимый доверенный канал. На чистой Alpine сначала выполните `apk add --no-cache bash curl`. После установки введите `sb`.

## Основные функции

- **Развёртывание протоколов:** Xray VLESS Vision REALITY, Xray VLESS XHTTP REALITY, Xray Shadowsocks-2022, официальный сервер Hysteria 2, а также варианты sing-box для Vision, Shadowsocks-2022 и Hysteria 2.
- **Комбинированные конфигурации:** связка Xray + Hysteria 2 и связка sing-box Vision + Hysteria 2 + Shadowsocks-2022. Вторая по замыслу не включает XHTTP.
- **Экспорт клиентских настроек:** ссылки/URI, QR-коды, Clash/Mihomo YAML, шаблоны исходящих подключений sing-box и JSON для XHTTP в v2rayN/v2rayNG.
- **Эксплуатация и диагностика:** тесты системы и загрузки, качество IP и маршрута, BBR/FQ с откатом, предпочтение IP, измерение DNS и поддерживаемые DoT/DoH, выбор часового пояса по номеру, Locale/NTP, установка и резервное копирование Wallos, Fail2Ban/logrotate, лимиты трафика, резервное копирование, диагностика и предварительная проверка.
- **Операции:** Reality в один клик, быстрый/строгий режим (`ABOX_FAST`), фиксированные версии ядер с откатом при сбое, добавление/отзыв нескольких UUID на сервере, экспорт URI/Base64/Clash и проверка доступности источников загрузки.
- **Зеркала ядер:** Release [`A-Box Core Binary Mirrors`](https://github.com/alariclin/A-Box/releases/tag/core-binaries) хранит фиксированные совместимые версии и версионированные копии последних официальных стабильных сборок Xray, sing-box и Hysteria. Еженедельный workflow исключает draft/prerelease, проверяет официальный SHA-256 и архитектуру активов, а версию исполняемого файла запускает для проверки там, где это возможно на CI runner; старые версии сохраняются для отката. Перед установкой скрипт дополнительно проверяет фактическую версию бинарного файла на целевой системе. При сбое upstream сначала пробуется зеркало с тем же тегом, затем фиксированная совместимая версия. `SHA256SUMS` — манифест целостности в том же Release, а не независимая подпись; подробности — в [`mirrors/README.md`](mirrors/README.md).
- **Работа с кандидатами SNI:** локальные полная и облегчённая проверки, просмотр сохранённых результатов, проверка входных данных, ограничение размера и количества строк, удаление дубликатов и переход к корректному локальному кэшу или соседнему файлу данных, если он доступен.
- **Обслуживание:** контролируемое OTA-обновление скрипта с показом SHA-256 и явным подтверждением, обновление Geo-данных Xray и отдельное обновление ядра без сброса параметров узла.
- **Защитные механизмы:** предварительные проверки перед развёртыванием, контролируемые изменения состояния управляемых служб, обработка правил брандмауэра и механизмы отката для поддерживаемых операций.
- **WARP в один клик и разделение трафика:** развёртывание Cloudflare WARP как нативного WireGuard-исходящего; пресеты стрим/CN-прямо/глобально; мультихост SOCKS5 с правилами по доменам.
- **DNS три режима:** только IPv4, только IPv6, dual-stack. 10 провайдеров, автопара v4/v6.

В репозитории есть стартовый список [`data/sni-candidates.txt`](data/sni-candidates.txt). Список SNI содержит только кандидатов. Наличие домена в списке **не гарантирует, что он доступен с конкретного VPS в данный момент или соответствует требованиям TLS/ALPN/SAN для выбранной конфигурации REALITY**. Проверяйте кандидатов из целевой сети перед использованием. Если получить корректный список или резервную копию не удаётся, процедура SNI прекращается, а непроверенные данные не используются.

### Инструменты

Все прежние функции сохранены: системный тест/скорость загрузки, проверка качества IP, полная и облегчённая проверка SNI, WARP в один клик и разделение трафика, Swap 2 ГБ, резервное копирование/восстановление, диагностика без секретов, предварительная проверка и экспорт подписок. Добавлены подпункты BBR/FQ (применение и откат), настройки хоста (предпочтение IP, обычный DNS, DoT только при поддержке бэкенда, измерение DNS, DoH в поддерживаемой конфигурации, часовой пояс/locale/NTP и предпочтение источника загрузки), а также установка, обновление, статус, резервное копирование Wallos и удаление контейнера с сохранением данных. BBR запускается только вручную и не применяется автоматически после установки протокола.

Для тестов система сначала обращается к проверенному зеркалу A-Box (Release `test-tools-mirror`) и запускает скрипт только после проверки по `SHA256SUMS`. Если зеркало недоступно или контрольная сумма не совпадает, откат к upstream-скрипту выполняется только при `ABOX_ALLOW_UNVERIFIED_UPSTREAM=1` (без проверки, без SHA-пина); иначе скрипт не запускается.

Wallos — необязательное приложение для учёта подписок. Установщик получает стабильную версию и соответствующий Docker-образ, а при недоступности upstream использует Release `wallos-mirror`. Резервная копия сначала создаётся во временный файл и проверяется, затем публикуется атомарно. По умолчанию Wallos привязан только к `127.0.0.1`; для удалённого доступа используйте HTTPS reverse proxy или SSH-туннель. Публикация HTTP без TLS на всех IPv4-интерфейсах требует явного `WALLOS_BIND_ADDRESS=0.0.0.0` и повторного подтверждения. Обновление зеркала сторонних скриптов требует ручного запуска workflow и подтверждения.

Оптимизация BBR/FQ не применяется без подтверждения. DNS-кандидаты сравниваются по реальным запросам с текущего VPS; результат характеризует только данное измерение, а не универсальный рейтинг. DoT включается только на поддерживаемом бэкенде и требует имени TLS-аутентификации upstream-сервера, чтобы systemd-resolved проверял сертификат (например, `1.1.1.1#cloudflare-dns.com` или `8.8.8.8#dns.google`); DoH использует `dnscrypt-proxy` в поддерживаемой конфигурации systemd-resolved. Для DNS и часового пояса предусмотрен откат.

Переключатель языка охватывает главное меню, меню обслуживания и новые инструменты; некоторые старые мастера протоколов и сообщения об ошибках всё ещё могут содержать китайский или английский текст.

## Командная строка

В репозитории файл называется `install.sh`. Примеры curl выше сохраняют его как `A-Box.sh`; подойдёт любое имя, если это этот скрипт.

Выполняйте команды из каталога, где находится загруженный скрипт:

| Команда | Назначение |
|---|---|
| `sudo bash A-Box.sh --help` | Показать справку командной строки |
| `sudo bash A-Box.sh --lang zh` / `--lang zh-tw` / `--lang en` / `--lang ja` / `--lang ru` / `--lang fa` | Выбрать язык интерфейса и открыть меню |
| `sudo bash A-Box.sh --self-test` | Запустить встроенные регрессионные тесты |
| `sudo bash A-Box.sh --preflight` или `--dry-run` | Предварительная проверка без развёртывания нового узла |
| `sudo bash A-Box.sh --status` | Показать управляемую конфигурацию и состояние служб |
| `sudo bash A-Box.sh --start` / `--stop` | Запустить/остановить управляемые службы |
| `sudo bash A-Box.sh --version` | Показать метаданные сборки скрипта |
| `sudo bash A-Box.sh --export-backup-key /secure/path/A-Box-recovery.key` | Экспортировать ключ восстановления в защищённый каталог |
| `sudo bash A-Box.sh --convert-legacy-backup OLD.tar.gz [OUTPUT_DIR]` | Преобразовать старую резервную копию в формат manifest v3 |

Храните ключ восстановления и резервные копии в защищённом месте. Успешный `--self-test` не заменяет предварительную проверку целевого сервера, реальную установку и тест совместимости клиентов.

## Системные требования

Скрипт содержит ветви совместимости для следующих сред; фактическая работоспособность зависит от версии ОС, системы инициализации, архитектуры, зависимостей, сети провайдера и доступности внешних загрузок.

| Параметр | Требование |
|---|---|
| Семейства ОС | Debian 10+, Ubuntu 20.04+, CentOS/RHEL/Rocky/AlmaLinux 8+ или Alpine Linux |
| Система инициализации | systemd или OpenRC |
| Архитектура CPU | amd64/x86_64 или arm64/aarch64 |
| Права | root или sudo |
| Сеть | Доступ к системным репозиториям и необходимым upstream/GitHub endpoints релизов |
| Интерфейс скрипта | Китайский, английский, русский и персидский; см. примечание о старых сообщениях |

В меню языка доступны китайский, английский, русский и персидский. Главное меню и обновлённые меню обслуживания переведены; некоторые старые сообщения мастеров протоколов по-прежнему двуязычны и могут содержать китайский/английский текст.

## Контрольный список для production

1. Изучите скрипт и используйте доверенный источник с фиксированной версией; не доверяйте сторонним зеркалам автоматически.
2. Перед развёртыванием запустите `--self-test` и `--preflight` на целевом VPS.
3. Проверьте правила firewall/security group у провайдера и совместимость выбранного протокола, портов и клиентов.
4. Храните ключ восстановления отдельно; перед разрушительными изменениями создавайте и проверяйте резервную копию.
5. Проверьте DNS, TLS, ALPN, SNI, доступность и работу клиента из фактических сетей использования. Прохождение CI само по себе не доказывает совместимость со всеми провайдерами VPS, ОС и клиентами.
